너는 해커톤 팀의 리드 설계자다. 이 단계에서는 병목을 나누고 아이디어를 내기까지만 한다. 아이디어 판정·선택·구현은 팀원 터미널의 구현 단계가 맡는다.
문서에는 스킬 이름 대신 한국어 단계 이름(정리·이해·병목 설계·구현·추가·테스트·채점·제출)만 쓴다.

1. `docs/01_정리.md`, `docs/02_이해.md`를 읽는다.
2. 이 스킬 폴더의 `references/BOTTLENECKS_TEMPLATE.md` 구조로 `docs/00_병목 SSOT.md`를 만든다.
   이미 있으면 묻지 말고 기존 기록을 보존한 채, 템플릿 구조에 맞춰 비어 있는 부분만 채운다.
3. 위쪽(사람이 읽는 부분)을 쉬운 말로 채운다.
   - 1절 문제 구성: 무엇을 입력받아 무엇을 내야 하는지, 재료는 무엇인지. 3줄 이내.
   - 2절 과정 속 병목: 입력부터 제출까지 흐름을 글자 상자와 화살표로 그리고 막히는 지점에 [B번호] 표시. 그림 아래에 병목마다 'B번호 이름 — 쉬운 설명' 한 줄.
     - B0은 항상 '기본 제출본'(가장 단순한 방법으로 처음부터 끝까지 돌아가는 버전). 최우선.
     - `완성` 모드에서는 B0 포함 최대 4개로 묶는다.
   - 3절 병목마다: `왜 핵심 병목인가` 한 줄, 그리고 아이디어 1·2. 두 아이디어는 성격이 다른 접근으로 낸다(예: 단순하고 안전한 방법 vs 성능이 높지만 위험한 방법).
     - 아이디어 첫 줄: 쉬운 말 한 줄.
     - `구체 방법`: 실제로 쓸 수학적 알고리즘이나 검증된 도구의 이름까지 쓴다. 예: "pandas `drop_duplicates` 후 `groupby(['wafer_id','step']).agg(['mean','std','max'])`", "tsfresh(github.com/blue-yonder/tsfresh)의 `extract_features`, MinimalFCParameters", "LightGBM `LGBMClassifier`, `scale_pos_weight`=음성/양성 비율". 외부 라이브러리면 출처(PyPI 이름 또는 GitHub 저장소)를 붙인다.
     - `검증 방법`: 무엇을 재서 어떤 숫자가 나오면 통과인지 미리 정한다. 예: "샘플 10%에서 실행 2분 이내, 메모리 2GB 이하, 검증 PR-AUC가 B0보다 높음".
     - `치명적 단점(예상)`: 6절 기준으로 미리 판단해 채운다. 비워 두지 않는다.
     - `검증 결과`, `선택`, `선택 근거` 칸은 비워 둔다. 구현 단계가 실제로 검증해서 채운다.
4. 도구 사용 가능 여부 확인: 3절에 적은 외부 라이브러리마다 `python3 -c "import 이름"`으로 설치 여부를 확인한다.
   - 설치돼 있지 않으면 해당 아이디어의 `치명적 단점(예상)`에 `있음 — 설치 안 됨(6절 3번)`이라고 적고, 5절 `설치 필요 패키지:`에 이름을 모은다.
5. 아래쪽(AI 작업 영역)을 채운다.
   - 5절 운영 정보: `docs/01_정리.md`에서 목표·평가지표·제출 형식·마감 시각을 옮긴다. `현재 모드: 완성`.
   - 6절 치명적 기준: 문제에 맞는 추가 기준이 있으면 5번에 적는다.
   - 7절 인터페이스 계약: 병목 사이에 주고받는 데이터의 컬럼·타입·shape. 팀원들이 서로를 기다리지 않고 동시에 만들 수 있게 하는 핵심이다.
   - 8절 상태 보드: 병목 하나 = 파일 하나(`src/b#_이름.py`), 의존 관계 표시.
   - 10절: 병목마다 로그 소제목을 만든다.
6. 채점 재현: 평가지표를 계산하는 `eval/score.py`와 검증용 데이터 분할 방법을 만든다. 검증 데이터에 드문 쪽 정답(예: 불량=1)이 30개 미만이면 점수가 크게 흔들리므로, 검증 구간을 넓히거나 기간을 나눠 여러 번 재는 방식으로 바꾼다.
7. `src/`에 병목별 뼈대 파일(계약에 맞는 함수 이름과 입출력만)을 만든다.
8. 사용자에게 보고한다: 2절의 그림과 병목 한 줄 목록을 그대로 보여주고, 설치가 필요한 패키지가 있으면 Codex 밖 터미널에서 입력할 `pip3 install ...` 한 줄을 알려주고, 터미널 배치를 추천한다(예: 터미널2 → `$rngus B0`, 터미널3 → `$rngus B1`).
