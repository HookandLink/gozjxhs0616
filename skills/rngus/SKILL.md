대상: 사용자가 함께 적은 B번호. 두 번째 단어가 있으면 담당자 이름으로 쓴다(없으면 `T-B#`).
문서에는 스킬 이름 대신 한국어 단계 이름만 쓴다. SSOT 1~4절은 쉬운 말로 한 줄씩, 숫자와 상세 내용은 9·10절에 쓴다.

## 0. 모드 확인 (SSOT 5절 `현재 모드:`)
검증은 두 모드 모두 반드시 한다. 모드는 검증의 규모만 바꾼다.
- `완성`: 빠른 검증. 데이터의 10% 샘플로, 아이디어마다 2분 이내. '둘을 합침'은 검토하지 않는다.
- `다듬기`: 정식 검증. 검증 데이터 전체로 재고, '둘을 합침'도 후보로 검증한다.

## 1. 맡기
- `docs/00_병목 SSOT.md`를 읽는다.
  - 다른 터미널이 이미 '진행중'으로 맡은 병목이면 손대지 않고, '대기' 상태인 다음 병목을 맡는다. 사용자에게 한 줄로 알린다.
  - 3절의 아이디어가 비어 있으면 스스로 한 줄씩 적고 진행한다.
- 8절 자기 행: 담당, 상태 = '진행중'. 10절 로그 한 줄.

## 2. 검증
- 후보: 아이디어 1, 아이디어 2 (다듬기 모드에서는 둘을 합친 것도. 말이 안 되거나 충돌하면 제외).
- 후보마다 3절 `구체 방법` 그대로 작은 실험 코드를 만들어 실제로 돌린다. 설명만 보고 판정하지 않는다.
  - `구체 방법`이 추상적이면, 먼저 알고리즘·라이브러리·함수 이름까지 구체화해서 3절을 고친 뒤 돌린다.
  - 라이브러리가 설치돼 있지 않으면 그 후보는 `탈락 — 설치 안 됨`으로 판정하고 5절 `설치 필요 패키지:`에 추가한다.
- 3절 `검증 방법`의 통과 기준대로 잰다. 기준이 비어 있으면 최소한 실행시간·메모리·`eval/score.py`로 B0 대비 점수를 잰다.
- 9절에 후보마다 한 행: `측정 항목 | 통과 기준 | 결과 | 판정`.
- 3절 각 아이디어의 `검증 결과:` 칸을 채운다: `통과 — 핵심 숫자` 또는 `탈락 — 쉬운 이유`. 예상(치명적 단점(예상))과 결과가 다르면 예상 칸 옆에 `→ 실제는 달랐음`을 붙인다.

## 3. 선택
- 검증을 통과한 후보 중 점수가 가장 좋은 것을 고르고(차이가 작으면 더 단순한 쪽), 3절 `선택:`과 `선택 근거:`(쉬운 말 한 줄)를 채운다.
- 모든 후보가 검증에서 탈락하면: 8절 상태 = '치명적', 4절에 `병목 | 치명적 약점(쉬운 말)` 행을 추가하고(보완책 칸은 비움) 여기서 멈춘다. 사용자에게 `$cnrk B#`을 안내한다.

## 4. 구현
- 검증 실험 코드를 바탕으로, 선택한 방식대로 사용자에게 묻지 않고 바로 구현한다. 자기 병목 파일만 수정한다.
- 의존하는 병목이 미완료면, 7절 계약에 맞는 작은 가짜 입력으로 먼저 개발한다.
- 구현 중 새로운 치명적 단점을 발견하면, 코드보다 먼저 3·4절에 적고 8절 상태 = '치명적'으로 바꾼 뒤 멈추고 `$cnrk B#`을 안내한다.
- 이 병목이 모델 예측을 만들면 `AGENTS.md`의 실험 저장 규약대로 검증·테스트 예측을 저장하고 registry에 한 줄 추가한다.
- 완료 시: 8절 상태 = '구현완료', 10절 로그 한 줄, 사용자에게 `$xptmxm B#` 안내.
