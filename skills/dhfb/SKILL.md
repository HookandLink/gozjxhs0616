목표: 감이 아니라 '틀린 것들의 공통점'으로 다음 병목을 찾는다. 15분 안에 끝낸다.
문서에는 스킬 이름 대신 한국어 단계 이름만 쓴다.

## 1. 준비
- `experiments/registry.csv`에서 검증 점수가 가장 높은 실험을 고르고, 그 검증 예측(`experiments/<id>_valid.npy`)과 고정 검증 구간(`eval/valid_ids.csv`)의 정답을 불러온다.
- 없으면 현재 파이프라인으로 검증 예측을 먼저 만들어 실험으로 저장한다.

## 2. 틀린 것 나누기
- 분류: 검증 데이터의 실제 양성 수만큼 상위 예측을 '예측 양성'으로 보고 잡은 것 / 놓친 것 / 오탐 / 정상으로 나눈다.
- 회귀: 오차 절댓값 상위 10%를 '크게 틀린 것'으로 본다.

## 3. 세 가지 렌즈로 보기
① **비교표**: 그룹별로 모든 컬럼의 평균(범주형은 비율)을 나란히 놓는다. 모델이 쓰지 않은 원본 컬럼도 반드시 넣는다. 쓰지 않은 컬럼에서 그룹 차이가 크면 가장 강한 단서다.
② **오류가 몰린 묶음**: 범주형 컬럼은 값별로, 숫자 컬럼은 5구간으로 묶어 '놓친 비율'을 전체 평균과 비교한다. 오류가 가장 몰린 묶음 상위 5개를 뽑는다. 양성이 5개 미만인 묶음은 우연일 수 있으니 제외한다.
③ **놓침 예측 나무**: 실제 양성만 모아서 '놓쳤는가(1) / 잡았는가(0)'를 맞히는 얕은 결정나무(sklearn `DecisionTreeClassifier`, `max_depth=2~3`, `class_weight="balanced"`, `min_samples_leaf=8`)를 학습하고 `export_text(..., show_weights=True)`로 분기 규칙을 출력한다. 오탐도 많으면 실제 음성만 모아 '오탐인가'로 한 번 더 한다(회귀는 '크게 틀렸는가'로).
   - 입력에는 원본 컬럼(모델이 쓰지 않은 것 포함)만 넣는다. 모델의 예측 점수는 넣지 않는다. 넣으면 "경계선 근처에서 틀린다"는 뻔한 규칙만 나오기 때문이다.

## 4. 가설 만들기
오류가 몰린 곳 상위 1~2개마다 세 줄을 만든다.
- 쉬운 말: 모델이 어디서 틀리는지
- 현장 가설: 실제 현장에서 왜 그럴 수 있는지
- 근거 숫자: 3절 렌즈에서 나온 수치
그 정보가 예측 시점에 알 수 있는 정보인지 확인한다(데이터 누수 방지).

## 5. SSOT 반영
- 12절에 회차, 비교표 요약, 오류가 몰린 묶음, 나무 규칙, 가설을 기록한다.
- 가설마다 새 병목을 만든다: 2절 목록, 3절 상세, 8절 상태표(대기)에 추가.
  - 3절 `발견:`은 `오류분석 N회차`. 아이디어 1·2는 병목 설계 단계와 같은 규칙(구체 방법, 검증 방법, 치명적 단점(예상))으로 쓴다.

## 6. 보고
- 사용자에게: 모델이 주로 틀리는 곳 3줄, 새 병목 목록(쉬운 말), 터미널 배치 추천(예: 터미널2 → `$rngus B5`).
- SSOT 5절 마감 시각 기준 남은 시간이 45분 미만이면 새 병목을 만들지 말고 `$whgkq`를 안내한다.
